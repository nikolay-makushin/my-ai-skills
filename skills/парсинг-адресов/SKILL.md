# Парсинг адресов

Разбор адресов на сущности выполняет сам агент (LLM, NLP-подход) по правилам ниже.
Скрипт `scripts/io_tools.py` используется только для надёжного ввода-вывода:
определение кодировки (utf-8 / utf-16 / cp1251), разделителя и заголовка, чтение
XLSX и запись результата в Excel. Регулярки для разбора сущностей НЕ использовать.

Поддерживаемые входные форматы: `.csv`, `.txt`, `.xlsx`. Результат всегда
`.xlsx`: колонка `исходный_адрес` идёт ПЕРВОЙ, за ней колонки разбора (и `_extra`
колонки из исходной таблицы, если были).

## Шаг 1. Подготовка входного файла

```
python <папка_скила>/scripts/io_tools.py prepare --input <файл> --output <tmp>/prepare.json [--column "Имя" | --column 2] [--header auto|yes|no]
```

- Скрипт печатает: кодировку, разделитель, наличие заголовка, выбранную колонку адресов, число строк `count`.
- Убедись, что колонка с адресами выбрана верно; если в файле несколько колонок — передай нужную явно через `--column`.
- Результат в `prepare.json`: `rows = [{"address": "...", "extra": {...}}, ...]`.

## Шаг 2. NLP-разбор сущностей

Разбери каждый `address` из `prepare.json` на сущности по правилам ниже.

- Обработай ВСЕ строки: сумма объектов во всех батчах = `count` из шага 1.
- Батчами не более 50 адресов; каждый батч — отдельный JSON-файл (массив объектов) во временной папке ОС: `parsed_001.json`, `parsed_002.json`, ...

### Сущности (выходные колонки)

| Колонка | Что содержит | Пример |
|---|---|---|
| город | город из первой части | Санкт-Петербург |
| муниципалитет | внутригородской НП, если есть | Колпино, Шушары |
| тип_муниципалитета | город / поселок / деревня | поселок |
| тип_улицы | слово-тип объекта | шоссе, линия, территория |
| улица | название без слова-типа | Суздальское, Реки Смоленки |
| дом | номер или диапазон | 22, 1-3 |
| корпус | цифры после `к` | 11 |
| строение | цифры после `с` | 1 |
| литера | остальные буквы | АЗ, бА, Ч |

В выходном файле колонка `исходный_адрес` идёт первой, после неё — колонки разбора.

### Правила разбора

1. Ожидаемый формат: `Город[, Муниципалитет], Улица, Дом` — элементы через запятую.
2. `город` — первый элемент.
3. Второй элемент — `муниципалитет`, только если это населённый пункт, а НЕ улица.
   - Признаки НП: префиксы `пос.`, `п.`, `дер.`, `г.`; либо известные внутригородские города (для Санкт-Петербурга: Зеленогорск, Колпино, Красное Село, Кронштадт, Ломоносов, Павловск, Петергоф, Пушкин, Сестрорецк).
   - Признак улицы — наличие слова-типа из п. 4.
   - НП без префикса (Зеленогорск, Колпино) → `тип_муниципалитета = город`; `пос.` → `поселок`; `дер.` → `деревня`.
4. Тип улицы может стоять ДО названия (`улица Архивная`, `шоссе Суздальское`, `дорога В Каменку`) или ПОСЛЕ (`Большой Сампсониевский проспект`, `15-я Васильевского острова линия`, `набережная Реки Смоленки`).
   Словарь типов: улица, проспект, шоссе, линия, набережная, проезд, площадь, дорога, переулок, тупик, бульвар, аллея, мост, остров, парк, территория (тер.), городок.
   В `тип_улицы` пишем каноничное слово (`тер.` → `территория`), в `улица` — название без типа в исходном падеже (`Реки Смоленки`, `В Каменку`).
5. Дом — последний элемент. Суффиксы разбираются слева направо:
   - `к<цифры>` → корпус: `58к11` → дом 58, корпус 11
   - `с<цифры>` → строение: `84с1` → дом 84, строение 1
   - остальные буквы → литера: `45А` → литера А; `116бА` → литера бА; `3Х` → литера Х
   - комбинации: `1к1Б` → дом 1, корпус 1, литера Б; `48к2В` → дом 48, корпус 2, литера В; `13к2АЗ` → дом 13, корпус 2, литера АЗ; `1-3Ч` → дом 1-3, литера Ч
6. Нет данных → пустая строка `""`. Ничего не теряй: номер дома обязателен в результате.

### Формат батча (parsed_NNN.json)

```json
[
  {
    "город": "Санкт-Петербург",
    "муниципалитет": "Шушары",
    "тип_муниципалитета": "поселок",
    "тип_улицы": "шоссе",
    "улица": "Колпинское",
    "дом": "58",
    "корпус": "11",
    "строение": "",
    "литера": "",
    "исходный_адрес": "Санкт-Петербург, пос. Шушары, Колпинское шоссе, 58к11",
    "_extra": {}
  }
]
```

- `_extra` — скопированный объект `extra` из `prepare.json` (если пуст — `{}`).
- Ключ `исходный_адрес` обязателен и равен исходной строке без изменений.

## Шаг 3. Сохранение результата

```
python <папка_скила>/scripts/io_tools.py save --data parsed_001.json parsed_002.json ... --source <исходный файл> --expected-count <count из шага 1>
```

- Записывает `<имя_исходника>_parsed.xlsx` в ту же папку, что и исходник (Excel, openpyxl).
- Порядок колонок: `исходный_адрес` первой, затем `город, муниципалитет, тип_муниципалитета, тип_улицы, улица, дом, корпус, строение, литера`, затем `_extra`-колонки исходной таблицы (если были).
- Опционально: `--sheets` — также записать лист с копией исходных данных (имя листа `Исходные данные`).
- Скрипт предупредит, если число строк не сходится или есть строки без дома / исходного адреса.

## Шаг 4. Проверка и отчёт

- Разбери предупреждения скрипта; сверь `count`, выборочно проверь 3–5 строк против исходника.
- Отчёт пользователю: путь к xlsx-файлу-результату, число строк, колонки результата, перечисление сложных случаев (муниципалитеты, диапазоны домов, литеры).

## Ограничения

- Формат заточен под российские адреса `Город[, НП], улица, дом`. Для других форматов разбирай по общим правилам сущностей; что не удалось распознать — оставь пустым и упомяни в отчёте.
- Скил не исправляет опечатки и не нормализует названия — только выделяет сущности.
- Редактирование существующего xlsx (изменение колонок на месте, форматирование) не входит в скил — результат всегда новый файл `*_parsed.xlsx` рядом с исходником.
